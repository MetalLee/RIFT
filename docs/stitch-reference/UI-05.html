代码规范与提交契约

本文档为 RIFT 架构团队制定的全局代码合成与重构标准。在执行任何文件写入操作（File Write）或补丁合成（Patch Synthesis）时，Agent 必须将以下契约强制作为无损前提。

01/

TypeScript 强类型与完整性

严格禁用 any 与 unknown 的未经卫语句直接解包。所有输出的工程代码必须通过严格的断言守卫验证：

typescript // 推荐契约模式 (示例) TS 5.4+ 
type Result<T, E = Error> = 
  | { success: true; data: T }
  | { success: false; error: E };

export function parseKernelPayload(raw: unknown): Result<KernelMeta> {
  // 显式结构校验，杜绝隐式类型穿透
  if (!isValidMeta(raw)) {
    return { success: false, error: new MalformedPayloadError() };
  }
  return { success: true, data: raw };
}
info

规范提示：若调用第三方无类型依赖，必须同时就地生成 *.d.ts 声明模块，绝不可直接使用跳过检查指令。

02/

提交记录标准化 (Conventional Commits)

执行 Git 提交流程时，所有生成的主题行必须遵循语义化动词前缀标准，包含原子范围与明确上下文：

feat(canvas): 引入双重缓冲重绘流水线 新增可感知特性或端点
refactor(kernel): 解耦元指令词法分析器 不改变外部行为的架构优化
